## 3. Technical Environment Notes (for the implementer)

GitHub sanitizes README HTML rendering. Keep these constraints in mind when generating code:

- `<style>` tags, `<script>` tags, and most CSS properties on inline `style=""` attributes are **stripped** by GitHub's HTML sanitizer when the README is rendered on github.com.
- CSS `@keyframes` animations defined via `<style>` blocks in the `.md` file **will not run** on github.com. Any animation effect must be **self-contained inside an SVG file** referenced via `<img src="...svg">` (using SVG-native SMIL `<animate>`/`<animateTransform>` tags, or CSS inside the SVG's own internal `<style>` — GitHub does not sanitize CSS embedded inside a standalone `.svg` asset the way it does the `.md` file's HTML).
- Therefore: any new animated visual effect (see hologram frame, Section 4.1) must be delivered as **a new standalone `.svg` (or animated `.gif`/`.webp` if SMIL isn't viable) asset file** hosted in the repo (e.g. `/assets/hologram-frame.svg`) and referenced with a normal `<img>` tag — not as inline CSS in the README markdown.
- The snake contribution animation is generated by a scheduled GitHub Action workflow (commonly `.github/workflows/snake.yml` using `Platane/snk@v3` or similar) that outputs SVG file(s) (commonly `dist/github-snake.svg` and `dist/github-snake-dark.svg`) which are then committed to an `output` branch and referenced in the README. Color changes belong in the **workflow YAML's action `with:` parameters**, not in the README markdown.

## 4. Requested Changes (IN SCOPE)

### 4.1 Hologram frame around the hero banner image
**Goal:** Add a decorative holographic-style frame/border around the existing hero image (Section 2, item 2) — without altering the image itself — so the portrait looks like it's displayed inside a futuristic holographic projection panel that visually matches the existing dark/neon aesthetic of the profile.

**Requirements:**
- Deliver as a new SVG asset (`/assets/hologram-frame.svg` or similar) layered on top of / around the existing hero image. Preferred technique: wrap the existing `<img>` in a `<picture>`/`<div>`-like composition using an HTML `<table>`-free layered approach that GitHub README supports — most robust option is to **composite the frame directly into a new SVG that embeds the original image via `<image xlink:href="...">`**, so the whole hero section becomes a single self-contained animated SVG. This guarantees the frame renders identically for all viewers regardless of sanitization.
- Visual style — holographic panel aesthetic:
  - Thin corner brackets (like a HUD/sci-fi targeting frame) at all four corners, in a cyan/electric-blue or violet accent color that complements the existing purple/green snake accent palette.
  - A subtle animated scan-line sweeping vertically or horizontally across the frame (SMIL `<animate>` on a semi-transparent gradient rect, looping, low opacity ~0.15–0.25 so it doesn't obscure the portrait).
  - A soft outer glow/border using an SVG `<filter>` (`feGaussianBlur` + `feMerge`) in the same cyan/violet hue, pulsing gently (opacity animation, ~3–4s ease-in-out loop).
  - Thin horizontal "data readout" hairlines or bracket ticks near the top/bottom edges (optional, minimal, low-opacity) to reinforce the "hologram projection" feel — keep it subtle, not busy.
  - Corner brackets and glow color should sit within the same dark theme: base background stays fully transparent/unchanged so the existing image is unobstructed; the frame is purely additive on top.
- **Must not** crop, resize, recolor, or otherwise alter the underlying portrait image or its existing `여기요 FanOps` text overlay.
- Must not affect load performance meaningfully — keep the SVG lightweight (no raster effects, vector/filter-based only).

### 4.2 Snake contribution animation — recolor to purple-blue
**Goal:** Change the snake's body/trail color (the part currently rendered green) to a purple-blue (violet-indigo) gradient or solid tone, so the whole snake animation reads as a cohesive blue-violet accent rather than green.

**Requirements:**
- Locate the snake-generation workflow (Section 3) and update its color configuration parameters (commonly `snake` / `dots` color arrays passed to the action, e.g. `color_snake`, `color_dots`, or a `--color-snake` CLI flag depending on the action used).
- Replace the current green snake color with a purple-blue value — suggested palette: a gradient from indigo (`#4C1D95`/`#5B21B6`) to electric blue (`#3B82F6`/`#2563EB`), or a single mid-tone violet-blue (`#6366F1`) if the action only supports a solid color, matching/complementing the existing violet accent already present in the graph's secondary color.
- Keep the animation mechanics, grid size, dark/light-mode SVG pair, and workflow schedule/trigger unchanged — this is a color-value-only change in the action configuration.

### 4.3 Contribution grid dots — subtle multi-color palette
**Goal:** Make the underlying contribution-level dots (the "empty"/level-graded cells the snake moves across, currently plain dark/green tones) slightly colorful — introduce a small amount of color variety across contribution intensity levels — while keeping it tasteful and NOT garish/rainbow/neon-clashing ("jangan norak").

**Requirements:**
- Update the same workflow's `color_dots` (or equivalent 4–5 step color-gradient array representing contribution levels from "no activity" to "highest activity") to use a restrained, harmonious multi-hue gradient instead of a single-hue (green) ramp.
- Suggested approach: keep the darkest/empty cell as the existing near-black/dark-grey base (unchanged, for contrast with the dark theme background), then step through 3–4 muted jewel tones as intensity increases — e.g. deep slate → muted teal → soft violet → warm amber/rose as the brightest accent — rather than a full rainbow. The goal is a subtle, elegant multi-tone gradient, not a saturated multi-color rainbow.
- Ensure sufficient contrast between adjacent levels so the contribution graph remains readable at a glance.
- Coordinate the dot palette with the new purple-blue snake color (4.2) so the whole graphic still reads as one cohesive color story (blue-violet dominant, with 1–2 muted accent hues), not competing palettes.
- Keep dark-mode/light-mode SVG variants (if both exist) each internally consistent with this same restrained palette logic, adjusted for background contrast as needed.
